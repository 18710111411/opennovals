## 一、核心设定（不可修改）

### 1.1 金手指：词条之眼

| 要素 | 设定 |
|------|------|
| **触发方式** | 主动注视目标 3 秒，词条浮现 |
| **查看消耗** | 白色/绿色 1/10、蓝色 2/10、紫色 5/10、金色 8/10 |
| **提取限制** | 每日 1 次，超限反噬（修为跌落/受伤） |
| **透支惩罚** | 短暂失明（1 炷香）+ 剧烈头痛 |
| **恢复方式** | 休息（1-2 时辰）、修为提升（自动 2/10） |

### 1.2 词条颜色体系

| 颜色 | 含义 | 示例 |
|------|------|------|
| 白色 | 普通属性 | [锋利 +1][坚固 +1] |
| 绿色 | 稀有属性 | [丹火亲和][剑法娴熟] |
| 蓝色 | 珍贵属性 | [一式万遍][剑意雏形] |
| 紫色 | 史诗属性 | [丹道传承][未激活] |
| 金色 | 传说属性 | [剑道宗师][护山大阵] |
| 红色 | 危险/敌意 | [杀意][恐惧] |
| 灰色 | 神秘/隐藏 | [神秘：真实目的不明][封印中] |
| 橙色 | 异常状态 | [紧张：第一次干这行][震惊] |

### 1.3 趣味词条系统

**必须包含的元素：**
- 性格类：【吃货：闻到吃的就走不动道】【话痨：不说会憋死】
- 状态类：【醉酒】【突破边缘】【走火入魔】
- 秘密类：【伪善：已害死 137 名同门】【替身：主人被封印】
- 变化类：词条随情况变化（嚣张→恐惧）

## 二、写作流程

### 2.1 章节标准

| 指标 | 标准 |
|------|------|
| **字数** | 6000-6800 字/集 |
| **五感描写** | ≥3 种（视觉/听觉/触觉/嗅觉/味觉） |
| **心理描写** | 15-20 处内心独白 |
| **情绪外化** | 100% 肢体反应（无直接情绪描述） |
| **对话穿插** | 每段对话都有动作/环境穿插 |
| **场景细节** | 每场景 1-2 处具体描写 |
| **趣味词条** | 至少 2 个新词条 |
| **限制展示** | 至少 1 次精神力消耗/克制心理 |

### 2.2 章节结构

```
1. 开场（500-800 字）
   - 承接上集悬念
   - 抛出本集看点（词条亮点）
   - 五感描写（环境/气氛）

2. 展开（3000-4000 字）
   - 主角利用词条推进剧情
   - 加入趣味词条（至少 2 个新词条）
   - 展示词条限制（精神力消耗/克制心理）
   - 对话穿插（动作/环境）

3. 反转/高潮（1500-2000 字）
   - 词条揭示关键信息
   - 打脸/碾压/越级挑战
   - 情绪外化（肢体反应）

4. 收尾（1000-1500 字）
   - 留钩子（下集悬念）
   - 主角心理活动（总结/规划）
   - 五感描写（时间流逝/环境变化）
```

## 三、协作流程

### 3.1 人类职责（老板大大）

| 事项 | 说明 |
|------|------|
| **方向决策** | 剧情走向/角色设定/爽点设计 |
| **质量审核** | 检查每章是否符合规则 |
| **趣味词条审批** | 审核新词条是否有趣/合理 |
| **GitHub 管理** | 仓库地址/权限管理 |
| **最终发布** | 上架决策/平台选择 |

### 3.2 AI 职责（阿钳🦞）

| 事项 | 说明 |
|------|------|
| **章节创作** | 按规则写作（6000-6800 字） |
| **规则自检** | 完成自检清单 |
| **趣味词条设计** | 提供新词条建议 |
| **文件整理** | 清理纯净版/版本管理 |
| **GitHub 推送** | 自动推送到仓库 |

### 3.3 协作流程图

```
人类决策 → AI 创作 → AI 自检 → 人类审核 → AI 修订 → AI 推送 → 循环
   ↓          ↓         ↓          ↓          ↓         ↓
剧情方向   按规则写   检查清单   质量把关   修改问题   GitHub
```

## 四、自检清单（AI 每章必查）

### 4.1 创作时自检

| 检查项 | 标准 | 检查方法 |
|--------|------|---------|
| **五感描写** | ≥3 种 | 搜索【视觉】【听觉】【触觉】【嗅觉】【味觉】 |
| **心理描写** | 15-20 处 | 搜索【心理描写】计数 |
| **情绪外化** | 100% | 无"心中一凛""震惊"等直接描述 |
| **对话穿插** | 每段都有 | 检查对话前后是否有动作/环境 |
| **场景细节** | 每场景 1-2 处 | 检查每个场景是否有具体描写 |
| **趣味词条** | ≥2 个 | 搜索【】内的趣味词条 |
| **限制展示** | ≥1 次 | 搜索【警告】【精神力】 |

### 4.2 推送前自检

| 检查项 | 标准 | 检查方法 |
|--------|------|---------|
| **字数** | 6000-6800 字 | wc -m 命令 |
| **标注清理** | 无【视觉】等标注 | sed 清理后检查 |
| **词条保留** | 正文词条保留 | 检查【角色·词条：[...]】 |
| **版本命名** | chapter-XXX-vN.md | 检查文件名 |
| **Git 提交** | 规范 commit message | 包含修订内容说明 |

## 五、版本管理

### 5.1 文件命名规范

```
chapter-XXX.md          # 原版（初稿）
chapter-XXX-v2.md       # 第 1 次修订
chapter-XXX-v3.md       # 第 2 次修订（大修版）
chapter-XXX-v4.md       # 第 3 次修订（扩写版）
chapters-clean/XXX.md   # 纯净版（无标注，可发布）
```

### 5.2 Git 提交规范

```bash
# 格式
git commit -m "版本 第 X 集（修订类型）

🔧 修订内容：
- 具体修改 1
- 具体修改 2

📊 本集目录：
1. 核心事件
2. 趣味词条
3. 伏笔"

# 示例
git commit -m "大修版 第 2 集（趣味词条 + 限制系统）

🔧 修订内容：
- 添加王富贵【吃货】【话痨】词条
- 展示精神力透支副作用
- 增加金色词条（演武场看守）

📊 本集目录：
1. 入住外门宿舍
2. 参观宗门
3. 演武场见金色词条"
```

### 5.3 GitHub 推送流程

```bash
# 1. 清理纯净版（删除标注，保留词条）
sed 's/【视觉：[^】]*】//g; s/【听觉：[^】]*】//g; ...' \
    chapter-XXX-vN.md > chapters-clean/XXX.md

# 2. 提交
git add chapters-clean/
git commit -m "规范 message"

# 3. 推送
git push origin main
```

## 八、常见问题处理

### 8.1 字数不足

**原因：** 描写不够详细/心理活动少/场景细节少

**解决方案：**
1. 增加五感描写（每个场景至少 2 种感官）
2. 增加心理活动（每次使用词条后必须有心理描写）
3. 增加场景细节（环境/气氛/道具）
4. 增加对话穿插（动作/表情/环境）

### 8.2 词条滥用

**原因：** 主角到处看词条，没有消耗感

**解决方案：**
1. 每次查看后显示精神力消耗
2. 主角心理活动提醒"不能乱用"
3. 设置透支惩罚（失明/头痛）
4. 关键剧情才使用词条

### 8.3 趣味词条不足

**原因：** 只写状态词条，忽略性格/秘密词条

**解决方案：**
1. 每个新角色至少 1 个趣味词条
2. 词条要有变化（随剧情推进）
3. 词条要有趣味性（吃货/话痨/装睡）
4. 词条要有信息量（暗示背景/目的）
